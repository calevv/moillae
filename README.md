# 모일래

친구 그룹이 **투표로 모일 시간을 정하는** 웹 앱입니다.
후보 시간을 여러 개 올리면 멤버들이 가능 / 불가능을 누르고, 방장이 가장 많이 모이는 시간으로 확정합니다.

- 배포 주소: <a href="https://moillae.vercel.app/">배포 사이트</a>
- 로그인 없이 둘러보기: 첫 화면 → 시작하기 → "로그인 없이 둘러보기" (더미 데이터로 전체 흐름을 볼 수 볼 수 있습니다.)

<br />

## 현재 상황

> 2026년 11월 기준

- 회원가입부터 그룹 만들기, 친구 초대, 모임 제안, 투표, 확정, 달력까지 **실제 데이터로 동작**합니다.
- 화면은 **모바일 우선**으로 만들었습니다. PC에서는 390px 앱 화면이 가운데에 보입니다. PC 전용 레이아웃은 이후 작업입니다.
- 친구의 투표나 참여는 **새로고침해야 반영**됩니다. 실시간 반영은 이후 작업입니다.
- 로그인은 이메일만 지원합니다. 구글, 카카오 로그인은 버튼만 있고 준비 중입니다.
- Supabase 연결 버전은 `feat/supabase` 브랜치에 있고, `main`은 로컬 데이터 버전입니다.

## 구현된 기능

### 로그인

- 이메일 회원가입, 로그인, 로그아웃
- 로그인이 필요한 화면 보호, 로그인 후 원래 가려던 화면으로 돌아오기 (`?next=`)
- 로그인 없이 둘러보기 (데모 모드, 서버에 저장하지 않음)

### 그룹

- 그룹 만들기 (만든 사람이 방장)
- 초대 링크 복사 (`/invite/초대코드`)
- 초대 화면: 로그인하지 않아도 모임 이름과 인원을 먼저 보고, 직접 "참여하기"
- 멤버 목록, 혼자인 그룹과 모임이 없는 그룹의 빈 화면

### 모임 제안과 투표

- 후보 시간 여러 개로 모임 제안 (공휴일 표시)
- 후보마다 가능 / 불가능 응답, 다시 누르면 미응답으로
- 가장 많이 가능한 후보 추천 표시, 아직 응답하지 않은 멤버 표시
- 방장만 시간 확정, 확정된 모임 화면
- 화면을 먼저 바꾸고 저장이 실패하면 되돌리기 (낙관적 업데이트)

### 홈과 달력

- 내 그룹 목록, 응답이 필요한 모임 알림
- 월간 달력: 확정된 모임과 투표 중인 후보 시간 표시, 날짜별 일정 목록
- 하단 탭 (홈, 달력)

## 기술적으로 고민한 것

### 로컬 먼저, 백엔드는 나중에 붙일 수 있게

처음에는 더미 데이터로 화면과 동작을 완성하고, 이후 Supabase를 붙였습니다.
화면 → 스토어(Zustand) → api 함수 → Supabase 순서로 역할을 나눠 두어서, Supabase를 붙일 때 **화면 코드는 거의 바꾸지 않고 `api` 안쪽만** 바꿨습니다.

### 하나의 Supabase 프로젝트를 여러 앱이 쓰는 구조

무료 플랜의 프로젝트 수 제한 안에서 여러 개인 프로젝트를 운영하려고, 앱마다 **Postgres 스키마를 분리**했습니다 (모일래는 `moillae` 스키마).
로그인 계정(`auth.users`)은 프로젝트 전체가 공유하기 때문에, 앱 안에서 쓰는 이름과 사진은 `moillae.profiles`에 따로 두고 처음 로그인할 때 만듭니다.

### 권한은 RLS로, 여러 테이블을 바꾸는 작업은 DB 함수로

별도 서버 없이 Supabase를 BaaS로 사용했습니다.

- 내가 속한 그룹의 데이터만 보이게 하는 권한은 **RLS 정책**으로 처리했습니다.
- 그룹 + 방장 멤버, 투표 + 후보처럼 여러 테이블에 한 번에 넣어야 하는 작업은 **DB 함수(RPC)** 로 묶어서, 중간에 실패하면 전부 취소되게 했습니다.

### 서버 데이터는 브라우저에 저장하지 않기

로컬 버전에서는 Zustand `persist`로 localStorage에 저장했지만, Supabase를 붙이면서 뺐습니다.
데이터의 원본이 서버로 바뀌었고, 한 기기를 여러 사람이 쓰면 앞사람의 데이터가 남을 수 있기 때문입니다. 로그아웃하면 스토어를 비웁니다.

## 트러블슈팅

### 1. 초대 링크로 가입하면 초대받은 그룹이 아니라 홈으로 가는 문제

**문제**
초대 링크로 들어온 사람이 기존 계정으로 로그인하면 그룹으로 잘 이동했지만, **회원가입을 하면 홈으로** 이동했습니다.

**원인**

- 로그인 후 돌아갈 주소를 라우터의 `location.state`(주소창에 보이지 않는 값)에 담아, 로그인 화면 → 이메일 로그인 → 회원가입으로 페이지마다 직접 넘기는 구조였습니다.
- 그래서 중간에 뒤로 가기, 첫 화면 거치기, 새 탭 열기 중 하나만 있어도 돌아갈 주소가 사라졌습니다.
- 초대 화면이 로그인해야만 보였기 때문에, 처음 온 친구는 무슨 모임인지 모른 채 로그인 화면부터 보게 되는 문제도 있었습니다.

**검토한 해결 방법**

- 탭 저장소(sessionStorage)에 초대 주소를 적어 두는 방법으로 증상은 해결됩니다.
- 하지만 탭이 바뀌거나, 이후 이메일 인증이나 소셜 로그인을 붙이면 같은 문제가 다시 생길 수 있어서 쓰지 않았습니다.

**해결**

- 돌아갈 주소를 **URL의 `?next=` 파라미터**로 옮겼습니다. 새로고침, 새 탭, 이메일 링크에서도 유지되고, 이후 이메일 인증(`emailRedirectTo`)과 소셜 로그인(`redirectTo`)에도 그대로 넘길 수 있습니다.
- `?next=https://다른사이트`처럼 외부로 보내는 **열린 리다이렉트를 막기 위해** `/`로 시작하는 앱 안 주소만 허용하고 `//`로 시작하는 주소도 막았습니다.
- 초대 화면을 **로그인 없이 볼 수 있게** 바꾸고, 모임 이름과 인원을 먼저 보여 준 뒤 사용자가 직접 "참여하기"를 누르게 했습니다.
- 아직 멤버가 아닌 사람은 RLS 때문에 그룹을 볼 수 없어서, 초대 코드로 **그룹 이름, 인원, 내가 멤버인지만** 돌려주는 DB 함수를 만들었습니다.

**배운 점**
증상이 난 한 곳을 고치기보다 "왜 끊길 수 있는 곳에 값을 들고 다니는지"를 따라가니, 사용자 흐름의 문제까지 같이 보였습니다. 오래 유지돼야 하는 값은 오래 유지되는 곳(URL)에 두는 게 맞았습니다.

### 2. 방금 만든 투표에 응답하면 저장이 실패하는 문제 (구현 전에 발견)

**문제**
화면을 먼저 바꾸기 위해 투표와 후보의 id를 앱에서 만들었는데(`crypto.randomUUID()`), 기존 DB 함수는 id를 DB에서 새로 만들었습니다. 그대로 두면 화면의 id와 DB의 id가 달라서, 방금 만든 투표에 응답할 때 "없는 후보"로 실패합니다.

**해결**
DB 함수가 **앱이 만든 id를 그대로 받아서** 쓰도록 바꿨습니다. 낙관적 업데이트에서는 화면과 서버가 같은 id를 써야 한다는 점을 기준으로 삼았습니다.

### 3. 권한이 없는 확정 요청이 에러 없이 끝나는 문제

**문제**
RLS에 막힌 `update`는 에러가 아니라 "0줄 바뀜"으로 조용히 끝납니다. 그래서 화면에서는 확정된 것처럼 보이다가 새로고침하면 원래대로 돌아갈 수 있습니다.

**해결**
`update` 뒤에 `.select()`로 바뀐 줄을 돌려받고, **0줄이면 실패로 처리**해서 화면을 되돌리도록 했습니다.

### 4. 데이터를 불러오기 전에 "그룹이 없어요"가 잠깐 보이는 문제

**문제**
로그인 직후 데이터가 도착하기 전, 홈에 빈 화면("아직 그룹이 없어요")이 잠깐 보였습니다.

**해결**
스토어에 `dataStatus`(`idle` / `loading` / `ready` / `error`)를 두고, 데이터가 준비됐을 때만 화면을 보여 주도록 했습니다. 불러오는 도중 로그아웃하거나 계정을 바꾸면 늦게 도착한 옛 응답은 버리게 했습니다.

## 앞으로 넣을 기능

### 1단계: 안정화

- 확정 취소
- 직접 만든 확인창과 안내창 (브라우저 기본 `confirm`, `alert` 대체)
- 프로필 화면 (이름 바꾸기, 로그아웃)
- 그룹 나가기, 그룹 이름 바꾸기
- Supabase DB 타입 자동 생성, 테스트 코드

### 2단계: 사용성 넓히기

- 구글, 카카오 로그인, 이메일 인증
- 실시간 반영 (Supabase Realtime)
- 초대 코드 재발급
- 달력 그룹 필터, 다가오는 일정 목록
- PC 레이아웃 (사이드 메뉴)

### 3단계: 큰 기능

- 홈 화면에 추가하는 앱 + 알림 (PWA, 웹 푸시)
- 공휴일 API 연동
- 서버 데이터 캐시 (TanStack Query 도입 검토)
- 개인 일정 공유, 빈 시간 찾기, 구글 캘린더 연동

## 폴더 구조

```
src/
├─ api/          Supabase 요청 (화면은 이 안쪽을 몰라도 됨)
├─ components/   화면 조각 (후보 카드, 하단 탭 등)
├─ data/         데모 모드용 더미 데이터
├─ hooks/        useCurrentUser, useNextPath
├─ layouts/      RootLayout, RequireAuth, TabLayout
├─ lib/          Supabase 클라이언트
├─ pages/        화면
├─ stores/       Zustand 스토어 (앱 데이터, 로그인 상태)
├─ types/        타입
└─ utils/        날짜, 달력, 공휴일, next 주소 검사
```
